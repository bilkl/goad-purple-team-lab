# Mercredi 14 octobre — premiers tests

[← Suivi du projet](../SUIVI.md) · [Captures de la séance](./preuves/2026-10-14/README.md)

## Objectif de la séance

Reprendre le lab, repérer ses services et réaliser un premier test avec une trace
Wazuh correspondante. Les tests concernent uniquement DC01 et WS01 du lab.

## Ce qui a été fait

1. Redémarrage des deux réseaux isolés, de Wazuh, puis de DC01 et WS01.
2. Vérification des services Windows, de la relation d'approbation et des deux agents Wazuh.
3. Reconnaissance de douze ports TCP sur chacune des deux machines.
4. Lecture de l'annuaire avec le compte `dave` fourni par le scénario GOAD.
5. Vérification d'une seule connexion SMB avec `bob`, à partir du mot de passe lu dans sa description.
6. Recherche de la trace correspondante dans Wazuh.

**Le compte initial est connu grâce au scénario du lab. Il s'agit d'un exercice
guidé, pas d'un accès découvert à l'aveugle.**

## Résultats en langage simple

### Les deux rôles du lab sont visibles

| Machine | Rôle | Services ouverts parmi les ports testés |
| --- | --- | --- |
| DC01 | Serveur central du domaine | DNS, Kerberos, annuaire LDAP, partage SMB, administration Windows et bureau à distance |
| WS01 | Serveur membre du domaine | Partage SMB, administration Windows et bureau à distance |

Le scan est limité aux ports 53, 88, 135, 139, 389, 445, 464, 636, 3268, 3269,
3389 et 5985. Il ne constitue pas un inventaire exhaustif de tous les ports.
La cartographie BloodHound n'a pas encore été réalisée.

### Une première faiblesse est confirmée

Le compte `dave` peut lire la description du compte `bob`. Cette description
contient le mot de passe de `bob` en clair. Une connexion SMB comme `bob` a
ensuite réussi sur DC01 avec cette valeur, sans devinette ni essai de dictionnaire.
Le mot de passe reste masqué et n'est pas publié.

**Conséquence démontrée :** un utilisateur du domaine peut récupérer un autre
compte à partir d'un renseignement lisible dans l'annuaire.

**Correction proposée :** retirer les mots de passe des descriptions, changer
le mot de passe exposé et vérifier les droits accordés au compte concerné.
Le lab reste volontairement vulnérable pendant l'exercice ; cette correction
n'a pas été appliquée aux machines de test.

La lecture LDAP montre aussi `bob` dans `wsadmin`, ainsi que `alice` et `carol`
dans `Domain Admins`. Ces appartenances ne prouvent pas encore une exécution
sur WS01 ni une compromission du domaine.

### Wazuh a enregistré la connexion

| Champ | Valeur observée |
| --- | --- |
| Heure de réception par Wazuh | 14 octobre 2026, 08:45:11 à Zurich (06:45:11 UTC) |
| Machine | DC01, agent dc |
| Compte | bob |
| Événement Windows | 4624, ouverture de session réseau, type 3 |
| Règle Wazuh | 100101 |
| Source | Hôte de test du lab, 192.168.56.1 |

Le test s'est déroulé à 06:45:10–06:45:11 UTC ; l'alerte a été reçue à
06:45:11.965 UTC. La concordance porte sur l'heure, le compte, la source et la machine.
La règle détecte une connexion réseau ; elle ne démontre pas à elle seule le vol
du mot de passe ni la lecture de sa description LDAP.

## Reproduction et preuves

Le script `kvm/scripts/initial-enumeration.py` reproduit la lecture LDAP et
l'unique connexion SMB. Il lit le compte de départ dans la configuration du
scénario GOAD ; il n'affiche ni n'exporte le mot de passe découvert.
Les résultats Nmap, les horodatages et les preuves détaillées restent dans
`kvm/logs/2026-10-14/`, exclus de Git. Seul ce résumé sans secret est publié.

Une dépendance manquante pour LDAP/NTLM a été ajoutée à l'environnement Python
isolé et épinglée : `pycryptodome==3.24.1`, qui fournit le module `Crypto`
([documentation officielle](https://www.pycryptodome.org/src/installation)).

## Contrôle complémentaire des horloges et preuves visuelles

Lors de la préparation des captures, les horloges Windows avaient environ sept
heures d'avance sur l'hôte. Les heures publiées ci-dessus sont celles du test
sur l'hôte et de la réception des alertes Wazuh, pas les heures internes Windows.
Le test initial utilisait NTLM ; aucun succès Kerberos n'est revendiqué.

Les deux VM ont été remises à l'heure UTC. Une lecture indépendante a mesuré
un écart d'environ 1,55 s sur DC01 et 0,52 s sur WS01 à 06:59 UTC. Le domaine
et les services Wazuh ont aussi été contrôlés pendant la correction. Les traces
initiales restent inchangées ; les [captures avant/après](./preuves/2026-10-14/README.md)
montrent les valeurs observées.
